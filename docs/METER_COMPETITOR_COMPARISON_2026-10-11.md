## Formulas, selection and boundaries

- **A2Tools:** single-target DPS uses damage / `max(1 second, last damage − first damage)`, immediately. Multi-target mode sums selected damage but divides by the **longest individual target duration**. Default Boss mode selects the latest boss involving self/party; `LastHitByMe` follows self/summons, with a latest-target fallback before identification; `MostRecent` follows the latest target. All Targets includes targets hit within its configured window, initially 120 seconds. A target's aggregates restart after a gap over 30 seconds. [Formula and floor, lines 245–273/470–504](https://github.com/taengu/A2Tools-DPS-Meter/blob/99b6bf7372b5f840192691584a7b08683cb04bbc/src-tauri/src/combat/dps_calculator.rs#L245), [modes, lines 633–759](https://github.com/taengu/A2Tools-DPS-Meter/blob/99b6bf7372b5f840192691584a7b08683cb04bbc/src-tauri/src/combat/dps_calculator.rs#L633), [reset, lines 1923–1937](https://github.com/taengu/A2Tools-DPS-Meter/blob/99b6bf7372b5f840192691584a7b08683cb04bbc/src-tauri/src/combat/data_storage.rs#L1923).
- **cyberbadger:** shared first-to-last-damage interval, minimum one second; a separate header clock continues while active. Default BossOnly excludes adds after boss engagement. Ordinary/boss-alive idle limits are 10/30 seconds; death, full-HP reset and battle-state evidence can end segments. Manual reset archives the segment; the last result remains until new combat. [Clocks, lines 182–187](https://github.com/cyberbadger6969/aion2-dps-meter/blob/95f46d0957ae9ad50193b6f8c7344be4edc15274/src/AionMeter.Core/Combat/Encounter.cs#L182), [filter, lines 225–250](https://github.com/cyberbadger6969/aion2-dps-meter/blob/95f46d0957ae9ad50193b6f8c7344be4edc15274/src/AionMeter.Core/Combat/CombatTracker.cs#L225), [defaults](https://github.com/cyberbadger6969/aion2-dps-meter/blob/95f46d0957ae9ad50193b6f8c7344be4edc15274/src/AionMeter.Core/Combat/MeterOptions.cs#L12).
- **SkeeveAN:** ALL DPS uses each player's own first-to-last-hit interval. Selected bosses use a shared boss-hit interval and include known-monster/add damage inside it. Group is the default scope setting; automatic reset is off, with a configurable ten-second default when enabled. History segments use a 120-second target gap. [Actual UI calls, lines 1061–1074](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/b99cb350d6ad510623a32568646f5c2944dbbd6d/Client/Ui/MainWindow.xaml.cs#L1061), [adds/formula](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/b99cb350d6ad510623a32568646f5c2944dbbd6d/Client/Combat/BossFight.cs#L20), [settings](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/b99cb350d6ad510623a32568646f5c2944dbbd6d/Client/Ui/MeterSettings.cs#L167), [history](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/b99cb350d6ad510623a32568646f5c2944dbbd6d/Client/History/FightSegmenter.cs#L20).
- **Sentinel/Companion:** selected actors share the earliest selected hit through the snapshot endpoint. Automatic boss display uses current time for twelve quiet seconds, then last hit; death freezes immediately. Resumption includes the quiet interval. Sentinel counts only boss-target damage and defaults to all actors; Companion automatically restricts a confirmed party. [Reference UI, lines 281–303](https://github.com/xzHannes/aion-companion/blob/dbc3c275fe1846c8a98b531b966d227cb4d0ca02/src/AionCompanion.App/MainWindow.xaml.cs#L281).

Sentinel's requested party filter falls back to all actors until confirmed, then restricts sums and interval. Manual finish retains its recorded endpoint. No one-second floor: zero-duration DPS is 0; subsecond live intervals can spike. [Core formula](../native/SentinelMeter/vendor/src/AionCompanion.Core/CombatEngine.cs#L507). Thus **600,000 / 20 seconds = 30,000 DPS**, versus **600,000 / 24 seconds = 25,000 DPS**. This remains possible within Sentinel's first twelve quiet seconds without confirmed death. It demonstrates a clock difference, not the user's proven cause.

## Remaining evidence and hypotheses

1. **Verified attribution gap:** the default payload intentionally excludes optional name catalogs for game-data rights reasons; leftover-summon recognition relies on unavailable names. Classless spirit basics also lack the post-pin [MIT owner fix, 2026-10-03 22:29:04](https://github.com/SkeeveAN/Aion-DPS-Meter/commit/f59fcfe3b7815a335ae8a944e99b94ac507093fa). Fresh explicit spawn/cast ownership still works. Unclassified sources can be discarded, reducing totals; class-prefixed unresolved sources can survive as orphan rows, reducing the owner's row or filtered totals. `DrainUnusedEvents()` discards `DrainResolvedOwners()` at [adapter line 512](../native/SentinelMeter/Adapted/LiveCaptureService.cs#L512), preventing retrospective recredit. Prioritize numeric spirit recognition and scoped confirmed-owner corrections, without importing excluded name tables.
2. **Verified missing correction:** the decoder skips tick effect identity. A later [MIT self-heal fix, 2026-10-03 22:29:37](https://github.com/SkeeveAN/Aion-DPS-Meter/commit/645f4b7dd6f4f52247ebba55d94e334799b84ded) prevents boss healing from inflating player damage; it cannot explain lower values.
3. **Support differences requiring encounter evidence:** A2Tools accepts damage ticks without trailing skill IDs and nested bundles through depth four. Sentinel requires tick flags/tail and excludes nested bundle expansion. These are potential missing-event paths, not established EU/Deus encodings. [Tick parser, line 428](https://github.com/taengu/A2Tools-DPS-Meter/blob/99b6bf7372b5f840192691584a7b08683cb04bbc/src-tauri/src/capture/stream_processor.rs#L428), [bundles, line 217](https://github.com/taengu/A2Tools-DPS-Meter/blob/99b6bf7372b5f840192691584a7b08683cb04bbc/src-tauri/src/capture/stream_processor.rs#L217).
4. **Excluded diagnosis:** A2Tools' [v2.0.48 framing correction](https://github.com/taengu/A2Tools-DPS-Meter/pull/20) already matches Sentinel's length-plus-prefix-minus-four rule.
